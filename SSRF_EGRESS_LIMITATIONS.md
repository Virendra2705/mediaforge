# SSRF egress controls and remaining limits

The Node HTTP paths in this patch use `server/outboundHttp.ts`. It rejects non-public IP answers, pins the selected validated address for each socket, preserves the original Host and TLS SNI, validates redirect destinations, and applies time and response-size limits. Direct media inspection/download, provider metadata HTTP calls, fixed EasyDown/RapidAPI API endpoints, and the yt-dlp binary download use this transport.

The transport does not constrain child processes. `yt-dlp` receives the requested source URL in `server/ytDlpService.ts` and performs its own DNS lookups, redirects, extractor-specific requests, and CDN/fragment requests. The application validates the initial URL and DNS answers before spawning it, and explicitly disables playlist expansion, but this does not pin subprocess connections or validate every secondary request. FFmpeg currently processes the local file downloaded by the guarded direct-media path; yt-dlp still performs remote network access for platform downloads.

The fixed EasyDown and RapidAPI calls connect only to configured code-level API hostnames through the pinned transport and do not follow redirects, so caller-supplied media URLs are sent as API request data rather than used as the local connection destination. The third-party API's own network behavior is outside this application's egress boundary.

**Deployment status:** do not treat this application as fully SSRF-protected for deployment while yt-dlp subprocesses can make unrestricted network connections. Enforce egress restrictions outside the application for both Node and all child processes. The policy should deny loopback, private, link-local, metadata, multicast, reserved, and IPv4-mapped IPv6 destinations after DNS resolution, and prevent direct egress that bypasses the controlled proxy/firewall. Validate redirects and DNS changes at that boundary. Termux runs as an unprivileged Android application; the available `iptables` executable does not grant permission to install firewall rules, so this checkout cannot enforce that boundary itself.
