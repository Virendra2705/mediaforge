# Fixing UPSTREAM_BOT_VERIFICATION_REQUIRED — Cookie Setup Guide

This guide explains how to configure `YTDLP_COOKIES` for MediaForge so that `yt-dlp` can authenticate requests and overcome `UPSTREAM_BOT_VERIFICATION_REQUIRED` errors.

---

## ⚠️ Important Tradeoff & Security Rules

> **CRITICAL**: The only way to bypass bot challenges is to provide `yt-dlp` with a signed-in session's cookies. Platforms actively protect their services against automated tools. Handing an automated server your session cookies risks rate-limiting, temporary bans, or permanent suspension of that account.
>
> - **NEVER USE YOUR PERSONAL ACCOUNT**: Create a separate, dedicated, throwaway account for this purpose.
> - **COOKIES EXPIRE**: Platforms invalidate sessions periodically. When `UPSTREAM_BOT_VERIFICATION_REQUIRED` reoccurs, re-export fresh cookies following this guide.
> - **DO NOT COMMIT SECRETS**: Never commit raw cookie files or strings to git repositories.

---

## Step 1 — Export Cookies from a Real Browser Session

1. In a desktop browser (Chrome, Firefox, or Edge), open a private window and log into your **dedicated/throwaway account** on the required platform (e.g., [YouTube](https://www.youtube.com)).
2. Install a reputable cookie export extension that outputs in **Netscape format** (for example, "Get cookies.txt LOCALLY" or "Export Cookies").
3. While on the platform tab and logged in, open the extension and export the cookies for the current domain.
4. Save the file as `cookies.txt`.
5. Verify that the exported file starts with:
   ```text
   # Netscape HTTP Cookie File
   # http://curl.haxx.se/rfc/cpost.html
   # This file was generated by...
   .youtube.com	TRUE	/	TRUE	1799999999	SID	<value>
   .youtube.com	TRUE	/	TRUE	1799999999	HSID	<value>
   ```
   *Note: Columns must be separated by true tab characters (`\t`), not spaces.*

## Step 2 — Configure `YTDLP_COOKIES` in Your Deployment

MediaForge's server (`server/ffmpeg.ts` & `server/ytDlpService.ts`) supports three flexible options:

### Option A — Mount as a File (Recommended for Docker / Kubernetes / Cloud Run)
Mount the file into your container (e.g. as a secret at `/run/secrets/ytdlp-cookies.txt`) and set:
```bash
YTDLP_COOKIES=/run/secrets/ytdlp-cookies.txt
```
MediaForge also checks `/run/secrets/cookies.txt` and `./cookies.txt` automatically.

### Option B — Multi-Line Environment Variable (Hosts with multi-line env support)
Paste the raw Netscape text directly:
```bash
YTDLP_COOKIES="# Netscape HTTP Cookie File
.youtube.com	TRUE	/	TRUE	1799999999	SID	...
.youtube.com	TRUE	/	TRUE	1799999999	HSID	..."
```

### Option C — Base64-Encoded Single Line (Safest for Cloud secret managers)
Convert the file to a single-line base64 string:
```bash
# Linux
base64 -w0 cookies.txt

# macOS
base64 -i cookies.txt
```
Set `YTDLP_COOKIES` to the resulting base64 output:
```bash
YTDLP_COOKIES="IyBOZXRzY2FwZSBIVFRQIENvb2tpZSBGaWxlCg..."
```
MediaForge detects base64 encoding automatically, decodes it into memory, validates the Netscape headers, and feeds it safely into `yt-dlp`.

## Step 3 — Verify Configuration on Startup

When the MediaForge server boots up, check the diagnostics in your startup log:
```text
COOKIES_CONFIGURED=YES (server-side secret)
```
- If it says `COOKIES_CONFIGURED=YES`: Cookies were parsed, validated, and loaded.
- If it says `COOKIES_CONFIGURED=NO`: The input failed validation. Verify that:
  1. The `# Netscape HTTP Cookie File` header line is included.
  2. Tab separators were not converted to spaces by a text editor.
  3. Placeholder strings (like `<contents of cookies.txt>`) are replaced with authentic cookies.

You can also check server status via the `/api/health` endpoint:
```bash
curl -s http://localhost:3000/api/health | jq .serverConfig
```

---

## Step 4 — RapidAPI Fallback Setup

When `yt-dlp` faces an unexpected challenge, MediaForge automatically attempts a fallback via RapidAPI's Social Download service.

1. Obtain an API key from RapidAPI for the **social-download-all-in-one** API.
2. Configure it in your deployment environment:
   ```bash
   RAPIDAPI_KEY="your_actual_rapidapi_key"
   ```
3. When both extraction layers encounter issues, error responses pinpoint the failure:
   - `HTTP 401` / `403`: RapidAPI key is invalid or not subscribed.
   - `HTTP 429`: RapidAPI plan quota exceeded.
   - `RAPIDAPI_KEY is not set`: The environment variable is missing or empty.

---

## Step 5 — Periodic Rotation

Cookies inevitably expire as platforms refresh security tokens. When `UPSTREAM_BOT_VERIFICATION_REQUIRED` reappears after normal operation, repeat Step 1 to export and deploy a fresh cookie set.
